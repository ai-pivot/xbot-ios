## 原生真实服务器验证

服务器：`https://xbot.energylt.com`。使用用户指定的本地两行账号文件；凭据只临时写入专用模拟器沙盒，读取后删除，不出现在命令参数、日志、报告或仓库中。

Debug 原生工具实际运行 `XbotAPI`、`ChatStore`、URLSession 和钥匙串，结果见 [原生验收报告](live-validation.json)：**10 个步骤通过**。

1. 登录并获取会话。
2. 主动失效登录会话后自动重新登录。
3. 模型 / 订阅 / 工具及用户设置读取，写回原值验证 RPC；包括压缩阈值和思考映射。
4. 创建、重命名专用测试会话。
5. 选择会话模型并重新读取。
6. 上传小型 PNG，认证下载并解码。
7. 发送测试消息，以原生 SSE 接收结果，重新读取持久化历史。
8. 创建分支并核对分支历史。
9. 发送测试消息后取消，确认处理结束。
10. 回退自己的测试历史并恢复草稿。

测试会话均在结束时删除，清理失败会将报告标为失败；不删除既有会话。设置仅写回原值。上传的小型测试图片没有可用删除接口，可能留在测试账号对象存储中。

桥接的 Node.js 客户端也使用该账号完成真实登录、会话树及模型 RPC 的只读检查，见 [桥接检查报告](relay-live-validation.json)。没有部署桥接或调用真实 APNs。
